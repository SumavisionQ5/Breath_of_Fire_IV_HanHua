# v16 系统文本回填技术定案

> 本文沉淀 v16 系列（v16 → v16b → v16c → v16d → v16e）迭代中破译的全部技术事实，
> 供接手者复现与继续 v16f。时间线记录见 [CHANGELOG.md](../CHANGELOG.md) v0.8.2。
> 当前基线：`bof4_chinese_v16e.bin`（740,731,544 B，SHA256 eeada38a…），
> 已通过模拟器实测（命名界面白字清晰可读，标题/立绘无回归）。

## 1. 系统文本段（seg2）结构

- 段签名 `sig = 0x801EC800`，结构：**256 项 u16 段内偏移表（512 B）+ 文本块数据区**
- 槽跨度 `[tbl[i], tbl[i+1])` 内含多页，页间以 `0x00` 分隔（与主文本块同构，
  `bof4lib.split_pages` 兼容处理）
- 译文映射到 (槽, 页)；未映射页**逐字节保留**；重组用 `b"\x00".join` 恒等还原
- ⚠️ **例外文件**：COMMU03 / SGAMEN / SHOP 的 seg2 表结构不同（`tbl[0] ≠ 512`），
  需单独适配解析后才能回填（v16f 待办）

## 2. 系统文本编码规则（与主文本不同）

| 字节 | 含义 |
|------|------|
| `0x20-0xFF`（单字节） | 原版小字库 idx 0-223（ASCII/标点/假名字形，v15 未动） |
| `0x12 XX` | 主字库全局池（汉字，强制套 0） |
| `0x13 XX` | 主字库全局池 idx+256 |
| `0x15 XX` | **图标控制码**（×=15 01 △=15 02 □=15 03 』=15 0A），`CTRL_LEN[0x15]=2` |
| `0x01` / `0x02` | `\n` / `\n---\n`（页分隔） |
| `0x05 XX` / `0x06` | `{色XX}` / `{/色}`（切窗语义） |

## 3. CLUT 决策矩阵（花屏根因修复）

| 范围 | 策略 | 依据 |
|------|------|------|
| `WORLD/*`（393 段） | rewrite 照旧（win0 奇数白化 + win9/B/C 套白） | v15 架构，场景文本渲染 |
| `SYSTEM/*`（66 段） | **一律保留原版**（逐字节 == 原版验证） | 系统界面无自有调色板，全靠 INIT 上传；rewrite 161 条目 → 标题/命名立绘花屏 |
| `SYSTEM/INIT.EMI` seg1/3/4 win0[9] | **唯一例外：白化为 7FFF** | 字芯 V=9 的显色位；v16 时代已被白化且 UI 无恙（安全性实证） |

- **花屏根因链**：`rewrite_clut` 改写 INIT 三个 CLUT 段 → 系统界面调色板污染。
  v16/快照/v16b 三版全部带该 rewrite，CLUT 污染掩盖了其他一切问题
  （seg4 尺寸假设从未被真正证伪）
- **面板保命位**：INIT seg1 win0 **[8]=(19,19,15) 恰为命名界面面板底色，绝不能动**
  （v16d 时代字芯 V=8 与面板同色 → 文字隐形，双重实证）

## 4. 原版字形规范（v16e 破译）

对原版字形数据（INIT seg7）像素值统计：

- **双峰分布：V=1（24.9%，暗描边）+ V=8（25.9%，亮字芯），9-15 为零**
- 描边结构 ≈ **8 邻域环**（80.9% 覆盖；旧文档「右下 2 向」与实证不符，已修正）
- 文字调色板 = INIT seg1 win0：
  - `[1] = (7,7,7)` 暗描边位
  - `[8] = (19,19,15)` 命名界面面板底色（兼原版字芯色 → 原版文字实为空心暗边样式）
  - `[9] = (20,21,22)` 灰阶峰值（**唯一可白化位**）
  - win0 无 7FFF 纯白
- 原版文字在面板上本就只靠暗描边显形（空心）；中文 12×12 密集汉字若照抄该观感，
  与背景对比度不足（v16d 实测字芯 V=8 = 面板同色 → 完全不可读）

### v16e 系统字库打包方案（用户实测定案）

```
描边 → V=1 (bit0)        # 暗色，继承原版描边位
字芯 → V=9 (bit0 + bit3) # INIT seg1/3/4 win0[9] 白化 7FFF → 纯白字芯
```

可读性测试图验证：白芯+暗边在浅底/深底双清晰（白芯单独浅底勉强、暗芯深底不可读）。

## 5. DEMO seg4 池复制架构

- DEMO.EMI 原版 4 段 → 追加 seg4（`sig=0x1C000200`，32768 B，容量 441 槽），
  文件 131072 → 163840 B，扩容搬移 + EXE LBA 表同步 109 项
- seg4 内容：**槽 0-329 = 全局池复制（V1+V9 打包）+ 槽 330-429 = DEMO 专属字 100 个**
- INIT seg7 同款打包（330 槽）→ DEMO 卸载后其他系统界面读池槽与 INIT 完全一致，
  **零污染**
- DEMO 专属字只解决 DEMO 自己 seg2 译文的用字；其他 SYSTEM 文件的 seg2 未译页
  原样保留日文

## 6. EMI 段表教训（崩溃根因）

段表 entry 16 B = `size(4) + sig(4) + 6B 配置参数 + 2B pad(0x2E)`。
**后 8 字节此前被误当「保留字段」**；全游戏 296 个字库段实测均为
`00 00 10 08 03 00 2E 2E`。追加新段必须照抄标准配置，否则游戏读段表即崩。

## 8. 已知边界与遗留问题

1. **标题菜单（START.EMI）无译文**：62 条 TSV 只覆盖存档/读档/设置/命名；
   标题乱码为预期未翻译表现（自 v15 起一致）
2. **1,138 条系统文本已翻译未回填**（`texts/tsv/system_text/system_text_remaining_translated.tsv`）：
   回填前需适配 COMMU03/SGAMEN/SHOP 非标准 seg2 表
3. **小字库字形资源未定位**：假名/ASCII 字芯仍走 [8]=面板色（空心暗边样式，
   与原版一致）；若要白芯化需动 [8]（有面板变白风险）
4. **VRAM 字体上传存在字节变换**：72 B 原始字形在即时存档内存中搜不到，
   变换算法待逆向（不影响功能）
5. **场景文字描边**：ring8 技术可复用，但需解决白字+环的配色方案
6. **取证技法**：RetroArch `.state` = RZIP 分块 zlib，解压后可在内存中搜
   调色板签名，验证用户实际加载的镜像版本
